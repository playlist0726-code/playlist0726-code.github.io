The question

Moving between a scene idea and different video-generation tools can fragment the creative workflow. Shot intention, camera choices, duration constraints, and prompt structure need to stay connected.

What I built

A directing interface for scene ideas, cinematic shot breakdowns, and copy-ready prompts for Kling, Runway, and Higgsfield workflows. The code includes platform/model configuration and server-function integration points.

Design & build decisions

01

Use the scene as the organizing unit

Keep visual intention and prompt output together so the creator can revise the direction before generating footage.

02

Make platform constraints explicit

Platform and model configuration includes duration options. A single generic prompt does not represent every tool’s available controls.

03

Separate the plan from the render

A shot plan is a creative specification. Actual video rendering still depends on the selected provider, service configuration, account access, and generation cost.

Evidence

Selected as a Top Project in the Handshake × OpenAI Codex Creator Challenge. The published demo is available below; source remains private.

What I learned

Working on AI films led me to build around directing decisions rather than treating generation itself as the finished product. The creator still owns the final judgment.

Current scope

Shot planning in the reviewed interface uses rule-based helper functions; separate rendering routes depend on external services. The published application may require sign-in or configured services. A generated prompt is not proof of a successful render. No measured time-saving, customer adoption, or production reliability claim is made here.

Next question

Test the same scene brief across supported workflows and document where a creator must revise the plan or prompt.
