COOPERATIVE BROWSER GAME

Human Enough!

Yokai, disguises, and a festival that rewards looking after your crew.

The question

How can a festival game make cooperation part of its rules, rather than simply put several players in the same world?

What I built

A 2–4 player browser game with a solo practice mode, seven yokai characters, six first-person festival minigames, shared escort objectives, and a cooperative boss encounter. Friends join with a room code; desktop and touch controls share the same game rules.

Design & build decisions

01

Give help a concrete action

Potion sharing, guest handoffs, disguise cover, help pings, and rescues let players directly support a teammate. The team win condition makes escorting guests a shared goal.

02

Keep rules on the server

The browser renders and sends actions. A shared simulation and the Node.js WebSocket server validate movement, sessions, rewards, and reconnects, instead of trusting each browser to award itself progress.

03

Make a complex world approachable

Solo and boss practice, a first-night checklist, a stall journal, contextual prompts, and adjustable graphics provide several ways to learn and enter the game.

Evidence

The repository includes deterministic rules tests, real WebSocket integration tests, production assets, and implementation notes for the minigames, disguises, character animation, and boss encounter.

What I learned

A convincing game world also needs understandable rules and recovery paths. This project made connection recovery, input feedback, and team coordination part of the product work alongside visual development.

Current scope

This is a competition submission, not an award claim. AI assisted development and asset workflows; gameplay does not depend on a live language model. The free hosted server can take 50 seconds or more to wake after inactivity. Try solo practice when reviewing alone.

Next question

Observe first-time players completing an escort, note where they hesitate, and use that evidence to simplify the first session.
